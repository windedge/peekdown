# v0.3.0 界面与交互差距分析（对照 Rust v0.2.0）

- 对照对象：Rust `C:/Seafile/Works/rust/peekdown` v0.2.0（HEAD `f9a0b7d`） vs Go `C:/Seafile/Works/go/peekdown` HEAD `be9ddf5`。
- 与 `docs/v0.3.0-acceptance.md` 的分工：验收矩阵回答"功能在不在"，本文回答"看起来像不像、用起来顺不顺"，因此侧重排版、着色、外壳质感、交互细节与阅读手感。
- 等级：**P0** 用户第一眼/第一条操作就会察觉；**P1** 每天用得到且明显不一致；**P2** 细节打磨；**P3** 可接受差异。
- 差距性质：功能缺失 / 视觉差异 / 交互缺失。
- 说明：mygo 的 `ui.List` 是否自带行间距未在本文实测；凡标注"待真机确认"的项，需在实机上观感确认后再定级。

### 明确不做

- 数学公式排版（#17，两版一致按纯文本）。
- `details/summary` 折叠、`mark/sub/sup` 专属样式（#7 明确不做）。

- 设置文件迁移（ADR 0002，保持 settings.json）。

### 最容易一次性拉齐的视觉项（用户感知最强，建议打包成一个 PR）

1. **行内代码底色 + 等宽**（1h）：全文最常见的内联元素，缺底色时整篇"灰扑扑"。
2. **段落间距**（1-2h）：Rust 每块 16px，Go 无；一条 `Padding`/`Margin` 规则即可，观感差异最大。
3. **主题 token 映射**（2h）：`theme.muted → Surface`、`theme.accent → 行内代码底`、`theme.secondary_active → 引用条`、`theme.link → Accent`；不动色板本身，只动用哪一个。
4. **代码块容器参数**（1h）：`Padding 10→12`、`Radius 6→theme.radius`、字号接 `MonoFontSize`；与 1/2 同批改完，正文、代码、引用三处观感同时到位。
5. **表格栅格线**（3h）：加 `BorderWidth` 行列线，是"用心做过的排版"与"网页默认样式"的分水岭。

这五项合计约 8 人时，改完后再看截图，`internal/view/view.go` 的观感与 Rust 的差距会从"明显不同"降到"细节不同"。
